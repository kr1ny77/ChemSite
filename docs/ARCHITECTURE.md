# Native ChemSite architecture

Godot 4.7 Forward+ is the production runtime. `Main` owns scene transitions; the active `ConstructionSite` owns the round, player, station proximity, task state, and HUD. `Player` is a CharacterBody3D with semantic InputMap actions. `GameHud` is a Control scene that emits answer, resume and exit signals. The native bank loads 40 verified Level 1 tasks or 39 verified Level 2 tasks from `data/chemistry/curated_tasks.json`. Level 2 uses four separate Blender-authored station models and the same site bounds. L2-050 remains review-required and excluded. The JSON also holds Levels 3–5 awaiting chemistry review and station mechanics. The original TypeScript bank remains in `legacy-web/src/chemistry/tasks/` and can be re-exported with `tools/chemistry/export_legacy_tasks.mjs`.

Career selects verified tasks deterministically through `task_scheduler.gd`, favoring weaker topics while alternating stations. A wrong answer records a mistake, advances to a different task, and moves a related verified task two questions later when possible. Completing five Level 1 tasks unlocks Level 2; older saves with earned stars migrate to the same unlock. Practice filters Level 1 by topic, runs without a timer and leaves career progress unchanged. `save_data.gd` stores versioned best score, stars, XP, completed rounds, topic mastery, mistakes and unlocked level in `user://progress.json`, migrating version-1 through version-3 saves. The macOS package includes an isolated `--qa-round` entry path for installed-runtime verification. Chemistry validation, station behavior, audio and progression remain separate systems as content scales.

The browser architecture that preceded this migration is preserved by Git history and `legacy-web/`.
